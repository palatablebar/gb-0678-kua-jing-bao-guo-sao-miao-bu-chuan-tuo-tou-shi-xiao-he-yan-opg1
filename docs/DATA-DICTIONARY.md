# 扫描时效定义

scan_id是扫描事件唯一键，parcel是包裹号。节点按收件、揽收、起运、清关、妥投顺序推进；可缺中间节点，但必须有收件。按event_time排序，received_time仅用于上传延迟展示。倒退扫描隔离，不改写先前妥投事件。妥投使用最早有效发生时刻。

## 正式承诺起算（业务裁决）

- **承运商揽收起算**：同一票存在有效揽收扫描（`PICKUP`，别名“揽收”）时，以最早揽收事件时刻作为唯一正式承诺起算点，时效结论为“正式”。
- **仓库收件只作受理记录**：仓库收件（`ACCEPT`，别名“收件”）保留在批次中，用于客服当天答复与受理核对，但不进入计时；页面与导出都写明“已有承运商揽收，仓库收件不作为正式起算（仅作受理答复记录）”。
- **缺揽收时的暂算回退**：没有揽收扫描时不臆造起算点，暂以仓库收件起算并明确标记“暂算”；补传揽收到达后按事件发生时刻重算，结论自动转为“正式”。暂算赔付单独汇总，不与正式赔付混列。
- **补传不改变起算时刻**：起算一律取事件发生时刻，不取上传时刻；揽收上传晚到（`upload_lag_hours` > 24）只做标记，不影响计时。
- **每票唯一结论**：同一批次的 `conclusions` 台账按包裹号唯一，同一包裹出现两份结论时拒绝归档（`DUPLICATE_CONCLUSION`）。页面、`GET /api/runs/<id>` 与证据导出读取同一份 `conclusions`，不做二次推导。
- **未裁决也要留痕**：收件与揽收都被隔离的包裹仍会得到一条 `clock_status=未裁决` 的记录（`decided=false`、`expected=0.00`），保证每个已映射包裹在台账中恰好出现一次，不静默消失。

两段记录以 `clock_records` 全量保留：每条含 `basis`（PICKUP/RECEIPT）、扫描号、事件时刻、上传时刻、是否采纳、未采用原因码与原因；`not_adopted_records` 只列未采用的记录。原因码包括 `PICKUP_SELECTED`、`RECEIPT_SUPERSEDED`、`RECEIPT_ADOPTED_FALLBACK`、`DUPLICATE_RECEIPT`、`DUPLICATE_PICKUP`。

揽收早于仓库收件的两段记录相互矛盾，整条揽收扫描隔离（`PICKUP_BEFORE_RECEIPT`），该票按暂算处理，不在矛盾数据上出正式结论。

## 时效与赔付

目的地JP/US/DE对应东京/纽约/柏林。时效以目的地工作日小时计算，周末与节假日停表。JP含2026-11-03与11-23，US含11-26，DE含10-03；支持按参数覆盖假日。未妥投计算至as_of，默认2026-11-18T00:00Z。每超时小时赔付1元，上限保价10%，reported为原申报赔付。

## 数据与幂等

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。空白行与分段重复表头写入 `cumulative_excluded`，保留源行号但注明“不参与计算”，与隔离行分列。

运行清单包括输入sha256、原始输入sha256（`original_sha256`）、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核与失效补传返回409。

同源重跑复用同一批次：不新增版本、承诺或赔款。补传按 `scan_id` 合并：完全相同的记录忽略（幂等，不升版本）；同 `scan_id` 不同取值返回409 `SUPPLEMENT_CONFLICT`，旧版结论完整保留。补传整份校验通过才进入事务；校验失败（表头不符、列数不符、空文件）返回422且不触碰旧结论。
